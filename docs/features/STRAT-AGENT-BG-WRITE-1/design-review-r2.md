# Design-gate review round 2 (codex gpt-5.6-terra/high) — REVISE

R1 status: #1 (read-only rejection) resolved. #4 (runner pid union) resolved. #5 (worker error handler) resolved. #2 partially resolved. #3 NOT resolved (invalid syntax). New findings:

1. **High — "string[]" is not valid mcp-surface grammar.** LEAF_TYPES in ts/src/mcp/contracts.ts:46 is {any, array, boolean, null, number, object, string}. The grammar's typed-array mechanism is the structured shape `{"$array": "string"}` (contracts.ts:98-101 element-validates via matchShape, so assertToolRequest gives boundary validation for free — a custom optionalStringArray helper is then unnecessary). Spec allowedTools?/disallowedTools? as `{"$array": "string"}` in mcp-surface.json.
2. **High — cancellation still doesn't own the terminal outcome.** The `cancelling` flag suppresses the parent exit sentinel, but the WORKER can commit its own rc=0 sentinel between the initial scan and terminate(); writeSentinelIfAbsent(...,130) then no-ops while cancel returns 'cancelled' and a later poll returns 'complete'. After terminate(), rescan and return the already-terminal result if the worker won, or centralize terminal-record ownership. Add this interleaving to the test plan. (design.md:159, :380)
3. **High — removing the codex-only guards accepts invalid discriminants.** With `agent`/`sandboxMode` declared as bare strings and casts at server.ts:113, an unknown agent falls into the codex branch and an arbitrary sandboxMode is passed into codex argv and persisted. Retain explicit runtime validation (agent ∈ {claude, codex}, sandboxMode ∈ {read-only, workspace-write}) at the MCP boundary or in startBackgroundRun. (design.md:236; codex.ts:60)
4. **Medium — claude worker registry leaks completed runs.** Entries are only marked dead, never removed; a long-lived MCP server retains every Worker + run id. Delete registry entries once the terminal record is committed, keeping the filesystem record for polling. (design.md:219, :293)
