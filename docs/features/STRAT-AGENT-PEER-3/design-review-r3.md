1. **[med] The revised reservation contract still makes some admitted steer results discardable (r2-4, §5).**

   **Evidence:** `design.md:198-202` reserves a slot through the callback attempt and promises an attempt for every accepted result, but `design.md:201` sends all `refused` replies through the discardable best-effort queue. Refusal is also an outcome of an already-admitted request: `design.md:189` maps an `expectedTurnId` mismatch or a finished turn to `expired/refused`. The generated `/tmp/peer3-ts/v2/TurnSteerParams.ts:6-10` explicitly documents that the server rejects an active-turn precondition mismatch. Thus a steer can acquire a reservation, be sent, race turn completion, and receive a refusal that the new rules route into the unreserved queue. That queue drops incoming non-notices when full (`ts/src/connectors/peer-sidecar.ts:164-168`), evicts them for notices (`:165-169`), and removes them on shutdown (`:215-218`). The existing saturation and shutdown fixtures exercise these conditions (`ts/tests/connectors/peer-sidecar.test.ts:698-725,743-755`). This contradicts both the reservation guarantee and `design.md:234`; holding a slot alone does not preserve a result routed outside its reserved list.

   **Suggested fix:** Route by admission state, not status label. Every result for an admitted `reqId`, including `expired/refused` and any pre-send failure occurring after admission, must use its reserved result slot through the bounded callback attempt. Only requests rejected before admission should use best-effort callbacks. Extend the saturation/shutdown fixture with an admitted steer rejected by the server for a stale `expectedTurnId`, and require exactly one callback attempt and eventual slot release for that refusal.
