## Probe 3 — MCP binding, VALID (`mcpbind2.mjs`)

Adds a canUseTool callback so the permission layer and the tool-list layer can
be told apart, and records which tools reached the permission layer at all.

```javascript
import { ClaudeConnector } from "/Users/ruze/reg/my/forge/stratum/ts/dist/connectors/claude.js";
import { query as sdkQuery } from "/Users/ruze/reg/my/forge/stratum/ts/node_modules/@anthropic-ai/claude-agent-sdk/sdk.mjs";

const TARGET = "mcp__filesystem__list_allowed_directories";
const PROMPT = `Call the tool ${TARGET} exactly once, with no arguments. Then reply with exactly one line and nothing else: "TOOL_OK" if the call returned a result, or "TOOL_DENIED" if the tool is unavailable to you or the call was refused. Do not use any other tool. Do not explain.`;
const SAFETY = ["Edit", "Write", "NotebookEdit", "Bash"];

// Records what the permission layer was ASKED to decide. If a tool never reaches
// here, something upstream of permissions (i.e. the tool list) blocked it.
const asked = [];
const canUseTool = async (toolName, input) => {
  asked.push(toolName);
  if (toolName === TARGET || toolName === "ToolSearch") return { behavior: "allow", updatedInput: input ?? {} };
  return { behavior: "deny", message: "probe allows only the read-only target" };
};

// Seam injection: forward the connector's OWN options untouched, adding only the
// permission callback. `tools` is the variable under test and is never modified.
let sawTools;
const instrumentedQuery = (params) => {
  sawTools = params.options?.tools;
  return sdkQuery({ ...params, options: { ...params.options, canUseTool } });
};

const ARMS = {
  C_preset: { label: "C  positive control: preset (no allowedTools)", opts: { disallowedTools: SAFETY } },
  A_narrow: { label: "A  THE QUESTION: allowedTools=[Read]",          opts: { allowedTools: ["Read"], disallowedTools: SAFETY } },
  B_denied: { label: "B  MCP tool explicitly in disallowedTools",     opts: { allowedTools: ["Read"], disallowedTools: [...SAFETY, TARGET] } },
};

const arm = ARMS[process.argv[2]];
if (!arm) { console.error("arms:", Object.keys(ARMS).join(", ")); process.exit(2); }

const events = [];
let result, error;
try {
  result = await new ClaudeConnector({
    model: "claude-sonnet-5", cwd: "/Users/ruze/reg/my/forge/compose",
    ...arm.opts, query: instrumentedQuery, onEvent: (e) => events.push(e),
  }).run(PROMPT);
} catch (e) { error = e; }

const toolEvents = events.filter(e => e.kind === "tool_use_summary" || e.kind === "tool_result");
const targetResult = toolEvents.find(e => e.kind === "tool_result" && typeof e.metadata?.output === "string"
  && !e.metadata.output.includes("tool_reference"));

console.log(JSON.stringify({
  arm: arm.label,
  sdkToolsOption: sawTools,
  permissionLayerAsked: asked,
  targetReachedPermissionLayer: asked.includes(TARGET),
  said: String(result?.text ?? "").trim().slice(0, 80),
  targetResult: targetResult ? { ok: targetResult.metadata.ok, out: targetResult.metadata.output.slice(0, 300) } : null,
  error: error ? String(error.message ?? error).slice(0, 300) : null,
}, null, 2));
```

# Adversarial review (gpt-6-astra/medium, 2026-09-17) and adjudication

Review verdict: **NOT CLEAN**, 7 findings. Six upheld, one upheld as a methodology
critique whose alternative hypothesis was then refuted by a new arm. Every upheld finding
is corrected in `../design.md`. Recorded here rather than quietly fixed.

## Arm D2 — the arm the review correctly said was missing

The review's sharpest point: arm A received `["Read","ToolSearch"]`, because the fixed
connector appends ToolSearch. So arm A's success was equally explainable by "ToolSearch
dynamically made the target available" and did NOT isolate the tool list. Correct. There
was no arm with a literal `tools: ["Read"]`.

Two arms were run to settle it.

**Arm D (confounded, discarded).** `tools: ["Read"]`, no ToolSearch, prompt asks only for
the MCP call. Result: nothing invoked, TOOL_DENIED, 25,004 cache-creation tokens. This
looks like the tool list blocking, but it is not evidence: the model answered on turn 1,
before the MCP servers finished connecting, so it never reached the turn where schemas
appear. Discarded for the same class of reason as the first `mcpbind.mjs`.

**Arm D2 (decisive).** `allowedTools: ["Read","Bash"]`, `disallowedTools` includes
`ToolSearch`, so the fixed connector emits `tools: ["Read","Bash"]` exactly. The prompt
forces a Bash call FIRST, producing the post-connect continuation turn, then asks for the
MCP tool.

```
sdkToolsOption: ["Read", "Bash"]
invoked:        ["Bash", "mcp__filesystem__list_directory"]
results:        [ok:true "warm",  ok:true "{\"content\":\"[FILE] .DS_Store\n[DIR] .claude...\"}"]
said:           TOOL_OK
cacheCreation:  544635
```

**Conclusion: the tool list does not bind MCP tools.** With no ToolSearch anywhere in the
SDK options, the MCP tool was still discovered and invoked and returned real data. The
review's alternative explanation is refuted. The review was still right that the earlier
probe did not establish this.

**Second result, unplanned:** 544,635 cache-creation tokens independently reproduces the
2026-09-16 figure of 511,214 in the production shape. This is the genuine pre-fix
reproduction that review finding 3 correctly said the 156,992-vs-53,620 A/B was not.
