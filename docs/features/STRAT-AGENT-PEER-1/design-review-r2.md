# Design review r2 (Codex gpt-6-astra, run 00f9c5bc02be, 2026-09-15)

1. **should-fix — Completion can remove the peer before the caller subscribes, contradicting the fast-run notification guarantee.** In “Cancellation and failure isolation,” registering and immediately cleaning up does not ensure that “a subscriber that races the finish still gets its notice.” This also affects ordinary runs that finish between `ListAgents` and `SendMessage`. Define a terminal retention window and a poll fallback when subscription fails; limit guaranteed notices to subscriptions actually accepted.

2. **should-fix — Publishing peer metadata lacks an explicit failure-isolation contract.** “Wiring” spawns the sidecar after writing `meta.json`, then adds `peer` to that metadata, while waiting only for the process’s `spawn` event. That event does not establish successful registration. Specify that `peerName` is tentative unless readiness is confirmed, and make the parent’s subsequent metadata update best-effort. Its failure must neither reject an already-started run nor enter the existing metadata-write failure path that kills the run ([background.ts](/Users/ruze/reg/my/forge/stratum/ts/src/connectors/background.ts:187)). Add coverage for bind/write failure and peer-metadata persistence failure.

3. **should-fix — The golden flow uses a timing race to establish its essential precondition.** A child sleeping for one second may finish and trigger cleanup before the test’s two-second discovery window, especially after sidecar startup overhead. Replace the sleep with a controlled release: keep the child running until the requester has established its subscription, then release it to write the sentinel. Test already-completed runs separately against the explicitly chosen behavior.

**Round-1 assessment:** Cancellation identity is closed: a detached sidecar observes the wrapper’s identity without adding another signal target. The callback-directory rule and its conflict with temporary-directory tests are closed by the explicit same-directory allowance. Sidecar startup failures now have cleanup and diagnostic behavior, but caller-visible registration state and optional metadata persistence still need the isolation rules in finding 2.

The established listing and frame-delivery facts are accepted. These findings concern the proposed lifecycle and verification contracts, not missing implementation.
